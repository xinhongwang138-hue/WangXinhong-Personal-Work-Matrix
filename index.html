电商运营助手

Ecommerce Operation Assistant

店铺运营的动作散在表格和群里：库存、竞品、素材、投放各一套口径。这个工作台把它们收进一个系统， Agent 任务也要走审批和追踪。

P02 38,026 LOC

合同审批系统

Contract Approval

合同在邮件和 IM 里流转，审批规则靠人记。这套系统把会签 / 或签 / 条件分支做成可配置的流程引擎， 并留下不可篡改的审计链。

工程约束 TS strict + noUncheckedIndexedAccess、禁 any；金额一律 Decimal(18,2) 禁浮点；时间存 UTC、展示 Asia/Shanghai；定义快照不可变

企业知识库

06 / Boundary

已知边界

能跑的部分写清楚，跑不动的部分也写清楚。以下六条都是当前真实状态，不是「后续规划」。

6 items
current state
01

四个系统没有在线 demo

四套系统都依赖本地数据库或向量库，仓库给的是可复现的启动路径，不是一个点开就能用的链接。这个页面本身是静态站，不需要后端。

02

P03 没有测试套件

知识库仓库里只有 test/04-test_graph_flow.py 一个链路脚本，没有 pytest 套件；链路能跑通，但没有断言，回归仍靠人眼看节点输出。

03

外部服务需自备

大模型 Key、Milvus 集群、RAGFlow、Tavily 都不随仓库分发。缺 Key 时链路会明确失败，而不是返回编造的结果。

04

没有性能数字

未做并发压测，因此不写 QPS、P95、错误率；也没有覆盖率报告。要这些数字得先搭压测环境。

05

没有 CI 流水线

四个仓库都靠本地脚本跑测试，没有配置 GitHub Actions 之类的自动校验；改完代码是否回归，取决于有没有人手动跑。

06

界面以功能为先

四个系统都没有独立设计系统，也没有做无障碍审计；这个页面做了键盘可达与减动效适配，但没做完整 WCAG 验收。
