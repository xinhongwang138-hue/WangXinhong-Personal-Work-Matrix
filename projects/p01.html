04 / Reproduce

在自己机器上跑一遍

下面是从零拉起这个系统要的东西。缺依赖时链路会明确失败，不返回编造的结果。

启动命令
npm run dev
访问地址

http://127.0.0.1:3000/ask

还需要准备
  • LLM 网关与 Key
  • MySQL
  • Redis
  • PostgreSQL

不需要 Docker：本机起 MySQL / Redis / PostgreSQL 后直接跑 api 与 web。LLM 网关地址与 Key 从 .env.example 的 LLM_BASE_URL / LLM_API_KEY 填。仓里没有默认口令，得先用 DEMO_OWNER_PASSWORD 播一个；再把同一个口令写进 web/.env.local 的 DEMO_LOGIN_PASSWORD，登录页会多出一键进入的演示入口（不配则不显示）。

05 / Boundary

这个系统跑不到哪

能跑的部分写清楚，跑不动的部分也写清楚。以下是当前真实状态，不是「后续规划」。

01

没有在线 demo

这套系统依赖本地的 MySQL、Redis 与 PostgreSQL，仓库给的是可复现的启动路径，不是一个点开就能用的链接。这个页面本身是静态站，不需要后端。

02

LLM 网关与 Key 需自备

LangGraph Agent 走 OpenAI 兼容网关，LLM_BASE_URL / LLM_API_KEY / LLM_MODEL 不随仓库分发。缺 Key 时链路会明确失败，而不是返回编造的结果。

03

没有性能数字

未做并发压测，因此不写 QPS、P95、错误率；也没有覆盖率报告。要这些数字得先搭压测环境。

04

没有 CI 流水线

仓库靠本地脚本跑测试，没有配置 GitHub Actions 之类的自动校验；改完代码是否回归，取决于有没有人手动跑。

05

界面以功能为先

没有独立设计系统，也没有做无障碍审计；这个页面做了键盘可达与减动效适配，但没做完整 WCAG 验收。
