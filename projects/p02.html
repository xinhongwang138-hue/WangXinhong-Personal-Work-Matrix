04 / Reproduce

在自己机器上跑一遍

下面是从零拉起这个系统要的东西。缺依赖时链路会明确失败，不返回编造的结果。

启动命令
npm ci && npx prisma generate && next dev -p 3001
访问地址

http://127.0.0.1:3001/contracts

还需要准备
  • PostgreSQL 16

需要先起 PostgreSQL（端口 5432），并把 .env.example 里的 DATABASE_URL 改成实际库。默认账号 admin@example.com / Admin@12345 来自 prisma/seed.ts，仅本地开发用；登录页下方的演示快捷登录可按角色直接进入，不必输口令，生产构建默认关闭。

05 / Boundary

这个系统跑不到哪

能跑的部分写清楚，跑不动的部分也写清楚。以下是当前真实状态，不是「后续规划」。

01

没有在线 demo

流程引擎跑在本地的 PostgreSQL 上，仓库给的是可复现的启动路径，不是一个点开就能用的链接。这个页面本身是静态站，不需要后端。

02

外部依赖只有 PostgreSQL

不调用大模型、也不连外部服务，审批规则是自研流程引擎按配置执行的，所以缺依赖时只会是数据库连不上，不会返回编造的结果。

03

没有性能数字

未做并发压测，因此不写 QPS、P95、错误率；也没有覆盖率报告。要这些数字得先搭压测环境。

04

没有 CI 流水线

仓库靠本地脚本跑测试，没有配置 GitHub Actions 之类的自动校验；改完代码是否回归，取决于有没有人手动跑。

05

界面以功能为先

没有独立设计系统，也没有做无障碍审计；这个页面做了键盘可达与减动效适配，但没做完整 WCAG 验收。
