04 / Reproduce

在自己机器上跑一遍

下面是从零拉起这个系统要的东西。缺依赖时链路会明确失败，不返回编造的结果。

启动命令
docker compose up -d
访问地址

http://127.0.0.1:8011/chat.html

还需要准备
  • Milvus
  • MinIO
  • MongoDB
  • MinerU API
  • LLM Key
  • 本地 BGE-M3 模型

docker compose 起导入与查询两个 API。文档要先 POST 到 /upload 才会进 Milvus；BGE-M3 与 reranker 模型路径在 .env 里指定，缺模型时链路明确失败。

05 / Boundary

这个系统跑不到哪

能跑的部分写清楚，跑不动的部分也写清楚。以下是当前真实状态，不是「后续规划」。

01

没有在线 demo

检索链路依赖本地的 Milvus、MinIO 与 MongoDB，仓库给的是可复现的启动路径，不是一个点开就能用的链接。这个页面本身是静态站，不需要后端。

02

没有测试套件

仓库里只有 test/04-test_graph_flow.py 一个链路脚本，没有 pytest 套件；链路能跑通，但没有断言，回归仍靠人眼看节点输出。

03

外部服务需自备

Milvus 集群、MinerU API、大模型 Key 与本地 BGE-M3 / reranker 模型都不随仓库分发。缺任一项时链路会明确失败，而不是返回编造的结果。

04

没有性能数字

未做并发压测，因此不写 QPS、P95、错误率；也没有覆盖率报告。要这些数字得先搭压测环境。

05

没有 CI 流水线

仓库靠本地脚本跑链路，没有配置 GitHub Actions 之类的自动校验；改完代码是否回归，取决于有没有人手动跑。

06

界面以功能为先

前端是静态页，没有独立设计系统，也没有做无障碍审计；这个页面做了键盘可达与减动效适配，但没做完整 WCAG 验收。
