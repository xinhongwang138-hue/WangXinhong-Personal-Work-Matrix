04 / Reproduce

在自己机器上跑一遍

下面是从零拉起这个系统要的东西。缺依赖时链路会明确失败，不返回编造的结果。

启动命令
docker compose -f docker-compose.demo.yml up -d && python main.py
访问地址

http://127.0.0.1:5173/

还需要准备
  • LLM 网关与 Key
  • Tavily API Key
  • RAGFlow
  • 只读 MySQL

demo compose 自带种子库；再在 ui/ 下 npm run dev 起前端，Vite 把 /api 与 /ws 代理到 127.0.0.1:8000。后端换端口是 DS_AGENT_PORT，前端要同步设 DS_AGENT_API_PORT（两个变量名不一样，漏一个就连不上）。模型网关、TAVILY_API_KEY、RAGFLOW_BASE_URL 与只读数据库连接串都要在 .env 里填。

05 / Boundary

这个系统跑不到哪

能跑的部分写清楚，跑不动的部分也写清楚。以下是当前真实状态，不是「后续规划」。

01

没有在线 demo

检索链路依赖本地的只读 MySQL 与外部的 RAGFlow，仓库给的是可复现的启动路径，不是一个点开就能用的链接。这个页面本身是静态站，不需要后端。

02

外部服务需自备

大模型 Key、Tavily API Key 与 RAGFlow 实例都不随仓库分发。缺任一项时链路会明确失败，而不是返回编造的结果。

03

提交数最少

四个项目里这个仓库的提交数最低（7 次），代码量也最小（3,105 行）。它是护栏与轨迹机制的验证样本，不是完整的生产系统。

04

没有性能数字

未做并发压测，因此不写 QPS、P95、错误率；也没有覆盖率报告。要这些数字得先搭压测环境。

05

没有 CI 流水线

仓库靠本地脚本跑测试，没有配置 GitHub Actions 之类的自动校验；改完代码是否回归，取决于有没有人手动跑。

06

界面以功能为先

没有独立设计系统，也没有做无障碍审计；这个页面做了键盘可达与减动效适配，但没做完整 WCAG 验收。
